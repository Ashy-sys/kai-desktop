# Kai Desktop V1.3 security model

## Permissions and data flow

Kai starts in Normal mode: there is no capture, microphone, or input polling. See Screen is a single-use grant. The Island hides briefly, the monitor under the pointer is captured into memory, resized to at most 1600 pixels on either edge, JPEG-compressed, sent over the authenticated Brain connection, then dropped. Nothing is written to disk. Control Screen is a visible five-minute session with a persistent Stop button, a twelve-round limit, a three-failure limit, repeated-action detection, and immediate cancellation. `Ctrl+Alt+K` is the global emergency stop; Escape also stops while the Island has focus.

Push-to-talk calls the WebView microphone API only after a click. Stopping releases every media track. The in-memory audio clip goes to the authenticated Brain transcription route and is dropped after transcription. Raw audio is not logged or saved. Speech output uses the local Windows/WebView speech synthesizer, is off by default, and speaks only a short summary.

## Controller boundary

The model never receives an OS handle. It can only propose typed actions. Rust validates session permission, monitor bounds, text length, key allowlists, timing, action count, repetition, and sensitive-action confirmation before using Windows `SendInput`. Arbitrary commands, scripts, executables, filesystem writes, and clipboard reads do not exist in the action schema. Application launch remains a fixed allowlist.

Windows UI Automation is the preferred semantic extension boundary. The V1.3 controller depends on the Windows UI Automation library so semantic element identity, accessible name, window identity, and bounding rectangles can be added without changing the model/controller trust boundary. Coordinate actions remain the fallback for applications that do not expose reliable accessibility data. Photoshop-specific scripting and general Skills execution are intentionally absent.

## Untrusted screen content

Pixels, OCR, webpages, documents, and accessibility names are untrusted data. The Brain vision instruction explicitly rejects on-screen requests to reveal secrets, weaken policy, execute code, or override system rules. Password contents are never requested, clipboard data is never read, and credential entry must be performed by the user. High-impact actions require confirmation for that exact action; initial session authorization is not blanket approval.

## Provider capabilities

Capability routing is explicit. Gemini 2.5 Flash, OpenAI's configured current vision model, and Groq Qwen 3.6 27B are eligible for images. Groq's text-default GPT-OSS model is not used for images. Transcription uses Gemini audio input, Groq Whisper Large V3 Turbo, or OpenAI GPT-4o Mini Transcribe through server-held credentials. Automated tests use mocks and make no provider requests.

## Known manual gates

A production installer must manually verify microphone permission, local voice availability, multi-monitor scaling, the global emergency shortcut, and Windows integrity-level restrictions on `SendInput`. No destructive live-control test is authorized.
